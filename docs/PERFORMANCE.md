# 墨迹性能与触控验收

## 硬件压感笔刷（2026-11-20）

开启设置中的“使用硬件压感”后，钢笔、各笔锋、书法笔、水墨笔和荧光笔均由硬件压力控制宽度。硬件压力使用独立的时间自适应平滑，真实压力决定每个采样点的宽度，后续输入保留已确定的宽度。书法、水墨和软笔采用更宽的粗细范围和较细的轻压响应，荧光笔采用较温和的压力范围。压力为 0.5 时对应设定笔宽。

压感笔的单击描点按接触期间的压力形成大小，轻抖仍合并成一个点。抬笔包只有结束坐标时会补齐轨迹，抬起后报告的零压力沿用最后接触压力，收笔时的有效轻压采样可自然收细。缺少压力信息的触控、鼠标和关闭硬件压感的输入继续使用原有笔锋与设定大小描点。

压力状态按笔画独立，并按需创建。已确定的压感笔画前缀直接进入现有分块几何缓存。水墨仍使用两层共享矢量轮廓，压力计算不会增加渲染图层。保存、回放、PDF 和笔刷风格切换保留对应压力与宽度。宽压感笔画的选择范围包含实际笔宽。

全量 766 项测试通过，新增检查覆盖全部八种笔锋、轻重压、压力释放、120/240 Hz 采样率、抖动、无效和缺失压力包、荧光笔、点画、时间戳溢出和 PDF 恢复。16 组实际 Win2D/DIB 压感渲染对照均通过，中位耗时 0.40–0.62 ms，P95 为 0.54–1.06 ms，脏区读回量相较整笔包围盒减少约 98.9%–99.0%。证据位于 `artifacts/pen-pressure-check/overlay-damage.json`。这是合成压感输入的本机渲染测量，实体笔的手感和端到端延迟仍需在对应硬件上确认。

WinUI 按当前笔触保留压力支持状态，在原生压力标志查询失效时采用事件自身提供的有效压力变化。Windows 将压力规范为 0–1，默认缺省值为 0.5。[Microsoft 压力属性文档](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.input.pointerpointproperties.pressure?view=windows-app-sdk-1.8)

## 千笔场景与混合输入（2026-11-20）

本次基准使用 Release x64、1280×720 Win2D 离屏画布，背景为 1,200 条笔迹、每条 100 个点。书写每帧加入四个采样点，共 120 帧，并强制 GPU 读回。平移与捏合分别测量 120 帧。

| 笔刷 | 书写中位 / P95 | 平移中位 / P95 | 捏合中位 / P95 |
|---|---:|---:|---:|
| 自然笔锋 | 0.92 / 1.48 ms | 0.95 / 1.45 ms | 1.23 / 3.39 ms |
| 书法笔锋 | 0.82 / 1.25 ms | 0.77 / 1.12 ms | 0.87 / 1.27 ms |
| 水墨笔锋 | 1.31 / 2.14 ms | 0.82 / 1.10 ms | 0.82 / 1.14 ms |

证据保存在 `artifacts/ink-performance-final/writing.json`。首次加载文档的栅格化会计入总耗时，中位数与 P95 描述持续绘制。实际触摸到屏幕发光的端到端延迟仍需在红外屏、压感笔与高刷显示器上测量。

- 屏幕批注根据上一帧的稳定前缀计算笔尖脏区，恢复后重新合成，取消触点时同时清除原笔迹范围。普通笔与荧光笔的八组检查相较逐帧读回整条活动笔迹的包围盒，读回字节减少 95.26%–98.84%。逐像素对照完整重绘，超过两级色值容差的通道数为零。
- 历史笔迹按分块索引查询，跳过空块。平移复用栅格，捏合期间持续复用缓存，抬指后恢复目标比例的精细栅格。低倍率下新增分块按显示比例采样，历史分块的栅格内存预算保持约 49 MiB。千笔测试中的平移与捏合均未触发历史缓存整体重建。
- Win32 覆盖层和 WinUI 画布补采合并输入，依次保留原始坐标和时间戳。覆盖层为一组历史采样提交一次绘制，拥塞时的绘制间隔预算调整为约 4.17 ms。补采顺序遵循 Windows 的逆时间历史数组约定。[Microsoft 输入历史文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getpointerpeninfohistory)
- 硬件压力标志与倾斜数据进入存储模型，倾斜笔尖与水墨深色内层共用屏幕、回放和 PDF 的矢量轮廓。荧光笔保持固定笔宽，轻抖单击继续以设定笔宽描点。
- 压感笔优先按输入屏幕隔离触摸。手掌先分类再参与双指配对，接触面积在移动中变大时取消误写并切换擦除。手势中心的平移与缩放组合修正了两指跟随偏移。
- 停笔识别支持直线、圆、椭圆、三角形、矩形、平行四边形、十二边立方体线框和相交坐标轴。按轨迹距离重采样，降低收笔抖动与采样率对拟合的影响。吸附后继续拖动可微调端点、顶点或尺寸，抬笔原子替换源笔画，撤销恢复原墨迹。
- 设置提供硬件压感、倾斜映射、笔优先、手掌擦、识别类型、300–1,500 ms 停笔等待和 1°–12° 方向吸附容差。默认等待 450 ms，方向容差 5°，支持水平、垂直和 45° 方向。

734 项域测试通过。原生设置窗口 252 项检查通过。覆盖层的八组笔刷对照、四组混合输入与自交笔迹切换对照、真实 Dispatcher 定时停笔预览检查通过，诊断进程退出码为 0。报告位于 `artifacts/ink-performance-final` 与 `artifacts/ink-performance-settings`。

运行 `artifacts/ink-performance/InkCanvas.exe --passthrough --writingcheck=D:\InkCanvas\artifacts\ink-performance-final` 可重新生成性能与渲染检查结果。此诊断会建立独立合成场景并在完成后退出。

## 前次内存与渲染优化（2026-11-18）

本轮快速书写另外使用实际 Win2D 离屏渲染基准（1280×720，120 帧，每帧新增 4 个点，逐帧强制读回以包含栅格耗时），绕过桌面是否可见的影响：

| 场景 | 原实现中位 / P95 | 当前实现中位 / P95 |
|---|---:|---:|
| 空白画布长笔画 | 2.35 / 10.09 ms | 0.59 / 1.01 ms |
| 240 条 × 100 点历史墨迹上书写 | 29.55 / 47.88 ms | 0.63 / 0.90 ms |

证据为 `artifacts/writing-render-before/writing.json` 与 `artifacts/writing-render-final/writing.json`。这是单机离屏基准，不代表触控硬件的输入延迟或实测屏幕 FPS；托管分配量从缓存前约 0.38 MB 增至约 0.50 MB / 120 帧。图形缓存有容量限制，窗口关闭释放缓存。

白板的历史墨迹缓存只在内容、视图、DPI、尺寸或回放状态变化时更新；纯追加笔画可直接补入缓存。长笔画按 64 段保留已稳定的几何块，只重建末端仍会变化的部分；整个几何组只填充一次，避免荧光笔重叠变深。400 点自交普通笔/荧光笔与完整重建的栅格结果逐像素一致。原生覆盖层只在队列已有更新包时跳过中间帧的 GPU 工作，所有采样点仍进入墨迹模型，抬笔强制提交。

复现：`InkCanvas.exe --passthrough --writingcheck=D:\InkCanvas\artifacts\writingcheck`。原 `--perfcheck` 用于下列内存基准；隐藏墨迹时其渲染耗时不能代表实际绘制性能。

在同一台 Windows 开发机、1920×1080 覆盖层、Release x64 下，对优化前后执行相同的 `--perfcheck` 工作负载。数字为单次进程内采样，单位 MiB；会随系统、驱动和屏幕分辨率变化。

| 场景 | 优化前 | 优化后 |
|---|---:|---:|
| 空闲工作集 | 175.9 MiB | 139.4 MiB |
| 空闲私有内存 | 86.2 MiB | 48.6 MiB |
| 首次渲染 240 条 × 100 点笔迹 | 305 ms | 92 ms |
| 同一文档追加 8 条笔迹 | 1770 ms | 193 ms |
| 追加绘制的托管分配量 | 222.8 MiB | 0.079 MiB |
| 160 次笔尖更新的托管分配量 | 69.7 MiB | 15.6 MiB |
| 大笔画结束并清空后的私有内存 | 192.5 MiB | 132.1 MiB |
| 6 次画板开关后的托管存活量（仅诊断时完整 GC） | 23.7 MiB | 3.0 MiB |

生产路径不调用强制 GC 或工作集裁剪。WinUI、图形驱动与 .NET 自身仍可能保留缓存，因此清屏不等于进程工作集立即回到启动值。

## 实现

- 空文档启动时不创建 D3D 设备或全屏 CPU/GPU 渲染缓存；直接写入分层窗口已有的 DIB，取消额外全屏帧副本。清屏、隐藏墨迹、进入画板时释放覆盖层渲染缓存。
- 每条笔迹使用一个 Winding 路径，保持自交并集与荧光笔透明度；采样段共用栈上顶点缓冲，不再为每段创建原生几何对象和数组。
- 原生几何按笔迹实例与几何版本缓存。追加笔迹保留已有缓存，修改和删除只淘汰相关条目；限制为最多 2048 条、100000 个采样点，按最近使用顺序淘汰。
- 活动笔迹缓冲按倍增方式扩容，避免每增长 64 像素就重新分配大数组。大笔画结束后释放较大缓冲。
- 画板与回放关闭时解除控制器订阅并移除 Win2D 画布；关闭窗口时停止拖动和弹窗定时器。工具栏主题元素列表由实例持有。
